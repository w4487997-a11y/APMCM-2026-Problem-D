# O-15：四层误差归因与资源成本审计

数据来源分三类，逐项标注：
- **本机实测**：`O15/timings.csv`、`O15/local_sa_timing.csv`（复跑脚本见下）
- **外部实测**：复审方授权环境 Kaiwu 1.4.3 记录（非本机）
- **平台记录 / NA**：历史真机任务页面截图；平台未单列的字段标 `NA`，未执行项标 `PENDING`

本机环境：Windows，Python 3.12.14，numpy 2.x，**无 GPU、无 SDK license、未连硬件**。
所有耗时均为单进程，`time.perf_counter()` 计时，重复 50 次取中位数（自检类 20 次）。

## 四、结论与写作口径

1. **本机精确枚举 0.03 ms、完整建模流水线 6 ms，比任何硬件排队/执行链路快 3–6 个数量级**；
   本文不声称量子加速，也不把求解器命中率当作优势证据。
2. 量化损失是本题最实质的误差来源：全池 8 位下最优候选塌入 6/21/24 个并列，损失 0.64+ V̂；
   两档分区编码把该损失降为 0，代价是牺牲非最优排序（见 `O11/oracle_caveat.md`）。
3. 采样误差在本地退火下已压到 0（30/30 种子命中），但**这是本地 CPU 结果**；
   真机样本量仅历史 2 次 × 10 条，不足以估计命中率。
4. 代理误差层缺 Q1 的独立复算口径，标 PENDING，不估算。
